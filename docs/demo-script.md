# LAKAZ demo script

Target duration is about two minutes. Rehearse with fictional Marie-Claire, 74, Rose-Hill. Check real band events, email login, phone GPS permission and the facility lookup before recording.

| Time | Action and spoken line |
|---|---|
| 0:00–0:45 | Press the help button. Show red “Needs help”, tap “I've got it”, and open the acknowledgement receipt. Say “After we drew the Prove It Works card, we added a receipt the carer can open after acknowledging a help alert. We'll refresh Lakaz and reopen the same receipt so you can see the acknowledgement was saved.” Refresh, sign in again if required, and reopen the same receipt. Point to the unchanged server timestamp. Resolve the help alert with “She is safe”. |
| 0:45–1:15 | Carry the band and phone away from the home beacon. Show the amber departure alert. Return to the beacon and show the “back home” banner and “At home since …”. Explain that the BLE home beacon detects departure and return. |
| 1:15–1:35 | Open Location. Say “The band has no GPS yet; this phone stands in for it in the demo.” Show the phone’s real position and its update time. |
| 1:35–1:50 | Open Find a health facility. Choose a district and show the official Open Data Mauritius directory and source. |
| 1:50–2:00 | Say “The escalation ladder, community alerts and closed-app push are our roadmap. The corresponding demo screens are sample data.” |

## Fallbacks

If phone GPS has no fix, show that state and its last update time. Do not call a recorded position current. If the physical departure/return fails, describe the intended BLE flow and clearly identify any sample demonstration. If the backend is unavailable, use a recorded successful receipt demonstration and label the recording. The phone GPS integration must be verified on the actual phone before the live pitch.
